# 계획 2 후속 항목 (계획 3 이후로 넘김)

계획 2(Windows 연동과 앱 1차)의 작업별 리뷰와 최종 리뷰에서 나왔지만 이번에 고치지 않은 항목이다.

## 수동 테스트로 먼저 확인할 것

- `tests/manual/plan2_app.md` 전체를 실행한다. 특히 다음 항목을 본다.
  - Docs/Slides 툴바 포커스 복구 경로: 최종 수정 1번으로, 단위 테스트가 없다.
  - R7 재확인 규칙(S1~S3): 텍스트 비교 때문에 공백 차이로 교체가 취소되는 일이 생기는지 본다.
  - 클립보드 실제 왕복(O): 소유자 없이 `OpenClipboard`를 여는 방식이 실제로 동작하는지 본다.
  - 설명 창의 드래그·크기 조절·높이 재조정.
  - 트레이에서 마지막 언어를 풀려고 할 때 체크가 원래대로 돌아오는지 본다.
  - 배지가 여러 모니터에서 커서 근처에 뜨는지 본다.
- 실제 CLI 다듬기 테스트가 한 번 실패(LlmFailed)했다가 다시 돌리니 통과했다. LLM 응답이 매번 달라서 생긴 일로 보이지만 확인되지 않았다. 다시 실패하면 로그의 `claude CLI process ended`, `stderr_tail_len`을 확인한다.

## 계획 3에서 처리할 만한 것

- **클립보드**
  - 텍스트가 없던 클립보드에 sentinel이나 번역문이 남는다(v5와 같음). `clear()`를 추가하고 시퀀스 번호로 보호한다.
  - `EmptyClipboard` 뒤에 `set_text`가 실패하면 복원을 시도하지 않는다.
  - sentinel을 쓰지 못하면 "선택 없음"으로 처리되어 Ctrl+A가 눌린다. 이때는 캡처를 중단해야 한다.
- **훅**
  - `start()`가 시간 초과되면 훅 스레드가 남는다.
  - `PostThreadMessageW`와 `UnhookWindowsHookEx`의 결과를 무시한다.
  - `GetMessageW`가 -1을 돌려줘도 참으로 처리한다.
  - `handle_event` 연결 코드에 테스트가 없다.
- **키 전송**
  - `SendInput`이 일부만 성공하면 Ctrl이 눌린 채로 남을 수 있다.
  - 교체(붙여넣기) 직전에는 Alt만 최대 0.5초 기다리고 Ctrl은 보지 않는다. LLM 응답을 기다리는 동안 사용자가 다른 단축키를 누르고 있으면 Ctrl+A/Ctrl+V가 수정키와 섞여 나갈 수 있다. 붙여넣기 전에 `wait_for_modifiers_released`로 Ctrl·Alt를 모두 확인하고, 시간이 지나면 교체를 취소한다(계획 3 최종 리뷰).
- **CLI**
  - stderr 읽기 스레드를 띄우지 못하면 파이프가 닫힌다.
  - 프로세스를 띄운 뒤 Job에 넣기 전 짧은 틈에 생긴 손자 프로세스는 Job을 빠져나간다.
  - 종료 코드를 `try_wait`로 읽으면 경쟁 상태가 생길 수 있다.
- **Settings**
  - 저장이 실패해도 사용자에게 알리지 않는다.
  - "(목록에 없음)" 항목이 목록을 갱신할 때까지 남는다.
  - 최소화된 창을 다시 열어도 복원되지 않는다.
  - Settings 창이 열린 상태에서 트레이로 Target을 바꾸면, 창의 옛 값이 저장 때 덮어쓴다.
  - Settings를 저장할 때마다 CLI를 다시 시작한다(v5와 같음). CLI 관련 값이 그대로면 재시작하지 않게 한다.
- **로그**
  - release에서 로그 파일을 만들지 못해도 기록이 남지 않는다.
  - 작은따옴표 기준 가리기가 필요 이상으로 가린다.
  - debug 빌드에서는 패닉 기본 출력이 사라진다.
- **설명 창**
  - whole_text에서 일부 문장에 한 언어가 빠지면 줄이 어긋난다(ct-core 검증으로 실제로는 막힘).
  - 드래그는 헤더·푸터에서만 된다.
- **교체 실패 문구**: 클립보드나 `SendInput` 실패에도 "교체 대상이 바뀌어…"가 뜬다. 안전하지만 정확하지 않다.
- **개인 사전**: core `update()`로 다른 항목 이름을 기존 표기로 바꾸는 것을 막지 못한다.
- **경고와 테스트 정리**
  - ct-win의 사용하지 않는 의존성 경고(crossbeam-channel, ct-core).
  - 각 작업의 테스트 빈틈(RED 증거 없음, 경계 사례 등).

## 결정 기록 (계획 2)

- R1: `ChromeAdapter::new`와 `RetryingInteraction::new`/`with_delay` 생성자 형태를 정했다.
- R2: ct-app을 lib+bin으로 바꾸고, 의존성 추가를 Task 12와 13에 나눴다.
- R3: UIA 요소 검색을 깊이 제한 walker로 한다(omnibox 20, render widget 10).
- R4: 자식 프로세스가 없는 ProcessEnded 경로는 진단 로그에서 제외했다.
- R5: `GestureAction::on_panic`을 추가했다. Alt는 배지를 숨기고 안내하고, Ctrl은 오류를 표시한다.
- R6: 트레이는 명령만 보내고, 실제 Target 변경 적용은 메인 루프가 한다.
- R7: 교체 직전 재확인에서 선택이 풀렸거나(선택 있던 경우) 입력란 텍스트가 바뀌었으면(선택 없던 경우) 교체를 취소한다. v5와 다르다.
- R8: 클립보드와 키 전송 구간을 프로세스 전체에서 하나씩만 실행한다(Alt와 Ctrl 계열이 섞이지 않게).
- R9: 간격 값 범위 제한, 오류 종류 로그, 스냅샷을 작업 스레드에서 잡기, 훅 패닉 때도 F15 해제.
