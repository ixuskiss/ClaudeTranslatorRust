# 계획 4 후속 항목 (계획 5 이후로 넘김)

계획 4(Google Sheets)의 작업별 리뷰와 최종 리뷰에서 나왔지만 고치지 않은 항목이다. 모두 병합을 막지 않는 수준으로 판정했다.

## 수동 테스트로 먼저 확인할 것 (`tests/manual/plan4_sheets.md`)

- H1·H7: 실제 Chrome에서 범위 붙여넣기와 쓰기 후 검증. 특히 compact JSON 키가 정렬된 순서로 다시 직렬화되는데(serde_json `preserve_order` 없음), Sheets가 이를 거부하면 `교체 결과를 확인할 수 없습니다…`가 뜬다. 그때는 `preserve_order`를 켠다.
- H9: `OpenClipboard(None)`(소유자 없음)으로 쓰기·복원이 실제로 되는지.
- 이름 상자 찾기, AutomationId·ValuePattern 읽기가 실제 Chrome에서 되는지.
- 표 보기: 숨긴 카드 목록 영역의 크기, 셀을 클릭한 뒤 Esc로 창이 닫히는지(안 되면 셀 TextInput을 focusable false로).

## 정리할 것

- `OpenClipboard` 재시도 래퍼가 `clipboard.rs`와 `format_clipboard.rs`에 두 벌 있고, `HTML_FORMAT` 상수도 두 곳에 있다.
- 범위 붙여넣기에서 Ctrl+V 전송이 일부만 성공(`sent > 0`)해도 클립보드를 복원한다. 실제로는 거의 생기지 않는다. 고친다면 `sent == 0`일 때만 복원한다.
- `table_size`가 `fit_size`의 여백 상수에 기대고 있다. 행 머리글 너비가 40px로 고정이라 아주 큰 행 번호는 잘릴 수 있다.

## 동작 차이와 경계 사례

- 주소: 접두어 뒤 공백을 한 번 더 지워 `Sheet1! A1`을 받아들인다. `A0`은 0행으로 계산한다.
- compact 데이터: 수식 목록(`"8"`)의 남는 항목과 패딩 바이트 값은 검사하지 않는다.
- HTML 파서: C1 제어 문자 참조(0x80~0x9F)를 cp1252로 바꾸지 않는다. 닫히지 않은 `<td>`는 앞 셀을 버린다. `</style>`은 대소문자를 구분한다. 아주 넓은 행에서 빈 열 찾기가 O(n²)이다(100만 칸 상한으로 제한됨).
- 교체 HTML: 새로 붙이는 `data-sheets-value`는 비ASCII를 그대로 쓴다(v5는 `\uXXXX`). 속성 찾기가 따옴표를 고려하지 않는다. 앞뒤 공백 처리에서 `\x1c`~`\x1f`가 Python과 다르다.
- 배치: 빈 번역을 "response ids do not match request"로 알린다. 교정 배치에서 빈 결과·무결성 검사를 모든 묶음이 끝난 뒤에 한다(실패 전에 LLM을 더 부를 수 있음). 사용자가 셀에 직접 쓴 `⟦n⟧`은 다시 번호를 매기지 않는다(무결성 실패로 안전하게 끝남).
- 배치 프롬프트: `targets` 배열이 공백 없이 직렬화된다(주석은 Python 구분자라고 적음). 응답 검증 순서가 v5와 조금 다르다.
- 번역 결과가 비면(실제로는 생기지 않음) 번역에서도 `수정할 부분이 없습니다.`가 뜬다.
- 범위 쓰기 재확인에서 문서·상태가 이미 달라도 이름 상자를 한 번 더 읽는다.

## 테스트 빈틈

## 결정 기록 (계획 4 실행 중)

- ct-sheets는 Task 1부터 ct-core에 의존한다(Windows 의존 없음).
- ct-win의 ct-sheets 의존은 Task 10에서 추가했다.
- `read_registered`가 돌려주는 바이트는 GlobalSize만큼 패딩될 수 있어, 사용자 정의 포맷은 선언된 길이로 자르고 HTML은 끝의 NUL을 지운다.
- 빈 transform 결과는 다시 읽지 않고 `NO_CHANGES`로 끝낸다.
- 클립보드 쓰기(`write_registered`)가 실패하면 사용자 클립보드를 복원한다(v5보다 안전).
- 범위 교정에서 바꾸지 않은 셀의 서식은 그대로 둔다(v5는 모든 텍스트 셀의 서식을 지웠음). 바뀐 셀은 표시 텍스트 비교로 찾는다.
- 확인용 Ctrl+C 전송이 실패하면 "확인 안 됨"으로 보고 검증 단계에 맡긴다. Ctrl+V 전송이 실패하면 클립보드를 복원하고 쓰기 실패로 처리한다.
- 작업은 서로 의존하지 않는 묶음을 git worktree 여러 개에서 병렬로 진행한 뒤 합쳤다.
